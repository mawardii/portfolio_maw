# iOS Interface Craft

Use this skill to raise the visual and interaction quality of a portfolio, dashboard, product page, or personal site while keeping the implementation practical.

## Workflow

1. Identify the primary audience, primary action, and most important proof.
2. Audit the current screen for hierarchy, density, spacing, color, affordances, responsive behavior, and accessibility.
3. Extract primitives from any references: layout rhythm, navigation density, card shape, type scale, image treatment, motion restraint, and empty space.
4. Define local tokens before broad edits: surface colors, text colors, borders, shadows, radius, spacing, and easing.
5. Compose the first viewport around the actual subject, not a generic hero. Make the page immediately show who it is, what they build, and evidence of capability.
6. Keep components quiet and scannable: tight copy, strong alignment, sparse borders, stable dimensions, and clear states.
7. Verify the result at desktop and mobile widths for text overlap, horizontal scroll, touch targets, contrast, and keyboard focus.

## Visual Rules

- Use white, off-white, soft gray, graphite, and one or two restrained accent colors. Avoid a one-hue theme.
- Prefer editorial grids, spacious bands, and compact repeated items over decorative card-heavy layouts.
- Keep cards at 8px radius unless the existing design system clearly uses another value.
- Use subtle material effects only when they improve hierarchy: blur, hairline borders, soft shadows, and muted translucency.
- Use realistic evidence blocks: roles, systems, methods, stack, evaluations, constraints, and outcomes.
- Do not hide weak copy behind animation. Rewrite vague sections into concrete proof before styling them.
- Do not introduce a build step, dependency, or icon system unless the repo already uses one or the user explicitly asks.

## Portfolio Quality Bar

- The first viewport must answer: who, domain, what kind of work, and why to keep scrolling.
- Every project should show problem, method, stack, evaluation or validation approach, and current status.
- AI/ML claims must separate confirmed experience from roadmap or aspirational work.
- The layout should feel calm under repeated reading, not just impressive in a screenshot.
